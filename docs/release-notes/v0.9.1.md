# v0.9.1

## Summary

- Tightened existing generated data labels ahead of v1 by fixing reprieved-row flags and replacing generic overview tier titles with canonical league names.
- Added verifier coverage so future releases fail when a row note says a club was reprieved but `wasReprieved` is not set.
- Updated roadmap and next-work docs to reflect the post-v0.9.0 baseline and the v0.9.1 correctness scope.

## Breaking Changes

None.

## Data Changes

- Rows with notes such as `Reprieved from re-election` or `Reprieved from relegation` now set `wasReprieved: true`.
- Generic overview metadata titles such as `League tables` are replaced with canonical season/level labels including `Premier League`, `Championship`, `League One`, `League Two`, and `Conference Premier`.
- Source `leagueId` values remain unchanged so consumers can still inspect the original Wikipedia heading identity.
- The legacy promotion aggregate was regenerated from source and now drops several stale top-flight relegation flags/lists where the current source no longer marks those clubs as relegated: `1892:tier1`, `1893:tier1`, `1894:tier1`, `1895:tier1`, `1896:tier1`, and `1987:tier1`.

## Bug Fixes

- Fixed reprieve detection in the shared table parser and typed output normalizer.
- Fixed generated tier metadata labels for overview pages whose source heading is generic but whose season/level position is unambiguous.

## Validation

- Added focused Jest coverage for reprieved row parsing, typed entry normalization, overview metadata title canonicalization, and verifier note/flag consistency.
- Added a data verifier check for rows with reprieve notes and missing `wasReprieved` flags.

## Consumer Notes

- No schema shape change is included in this release.
- `wasRelegated` semantics are unchanged for reprieved-from-relegation rows; this release adds the missing `wasReprieved` flag so consumers can distinguish those rows.
- This is not a tier 5 or level 6 backfill release.

## Known Limitations

- The 1957-58 Third Division North/South restructure still needs a v1 decision on whether bottom-half placement into the new Fourth Division should remain represented as ordinary relegation or gain more explicit restructure-placement metadata.
- Lower-tier historical coverage beyond the currently generated dataset remains deferred until after v1 readiness work.
